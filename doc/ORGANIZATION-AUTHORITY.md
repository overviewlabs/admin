# Organization authority and task recovery

Active human owners and administrators have all application permission keys in their own organization. Authorization reads the canonical active membership for each decision; missing or outdated grant rows do not reduce those roles. Demotion, suspension, or removal takes effect on the next decision. Operators, viewers, and agents retain their existing explicit grants and execution boundaries.

Owners and administrators may override internal assignment restrictions for active agents in the same organization. This does not confer another organization's access, access to personal credentials, host root privileges, or an exception to provider limits. Independent task reviews and governed credential actions retain their dedicated enforcement.

Failed-run retry follows the task's current state. A completed task is not run again. A task already running or awaiting a scheduled retry links to that current execution. A task reassigned since the failure opens the current task instead of resuming the previous agent's context. The scheduler checks status and assignee again under the task lock to prevent a race with reassignment or completion.

If dependencies prevent admission, Retry reports the unresolved dependency count and links back to the task instead of reporting a generic skipped wake. It does not bypass dependencies or create another execution.

An owner or administrator can grant or revoke CEO delegation through organization settings. The server records the granting user and time. The grant allows the named active CEO to answer ordinary task questions and confirmations with the CEO's real agent and run identity. It is not a human impersonation token. Delegation is revalidated at resolution, including the grantor's active management role, the CEO's current role and membership, and the task's current state. Imported company data cannot create or restore a grant.

Delegation does not establish factual rights, external entitlements, credentials, or completed work. Agents should act on explicit authorized instructions without repeatedly requesting the same approval, verify external facts where needed, and report the actual result and any remaining dependency.

Eligible ordinary pending decisions trigger a separate CEO decision run through the central interaction service. Startup and periodic reconciliation recover missed notifications. The run inspects the exact card under current authority; it does not check out or execute the original task. Personal, governed, independent-review, CEO-created, and terminal-task cards are excluded. A durable receipt per card and CEO prevents automatic replay after failed or skipped admission; the existing human inbox remains available.

`GET /api/companies/:companyId/it-diagnostics` supplies fixed, sanitized service-event metadata for the last 30 minutes. Active organization owners/admins can read it. Agents require an exact company/agent grant in the root-owned `/etc/overview-labs/it-diagnostics-grants.json`, active company membership, and their own running execution. Each read is audited. The root collector publishes `/var/lib/overview-labs-health/it-diagnostics.json`; reports older than five minutes return an explicit unavailable status. The default request has no query parameters. Optional paired ISO `since` and `until` parameters read retained sanitized history within the last 24 hours (maximum two hours per request); no other parameters, paths, or commands are accepted. Historical output includes explicit per-source scan gaps and truncation. `scanCoverage` describes the bounded queries performed; `coverage.complete` and `coverage.retentionVerified` remain false because earlier source retention is unverified, including for successful empty scans. Never present this as proof that no missing or rotated records existed. The route returns no raw journal messages, SQL, transcripts, or credentials. This metadata endpoint does not grant host root privileges or raw-log access.
