## Named storage library

The private Backblaze console now has readable file catalogs under `ovl-studio/studio/library/`. Start with `index.json` and `README.txt`. Blueprint catalogs are grouped by blueprint name under `blueprints/<name>/source/`; website catalogs are under `websites/<name>/previews/` and `websites/<name>/projects/`. Application attachments, saved Studio metadata, build jobs, Supabase files and WHOXOS assets are under `applications/`. Managed workspace catalogs use the workspace name plus a short stable identifier. Backup catalogs separate `databases/` and `deployments/`, then name the application.

Every `catalog.json` lists the original path, available original upload filename, size, checksum, modification time and underlying B2 object/byte range. These are private metadata catalogs, not extra copies of file payloads. Packed content, historical versions, existing URLs and recovery pointers stay valid. Tombstones and synthetic verification objects are excluded. Credentials and recovery keys are not exported.

The separate WMS bucket has `tql-wms/crm-documents/library/index.json`, `README.txt` and `documents/catalog.json`. It lists only Backblaze-backed CRM documents, with their document names and original filenames. Local-only documents are counted separately and never represented as cloud uploads. WMS database/deployment backups remain in the shared library's WMS backup catalogs.

`catalog.mjs`, `library-layout.mjs` and `catalog-metadata.py` build the catalogs after the normal verified file/backup sweep. Changed catalogs are uploaded with server-side encryption and checked by a SHA-256 read-back through Cloudflare. Unchanged catalogs are skipped. Root-owned `library-status.json` records the last successful refresh. The index is published after its catalogs; file-sync CPU and memory limits also cover the refresh. A failed refresh leaves the previous top-level index in place and reports a failed sweep; any partially written catalogs are retried on the next refresh.
