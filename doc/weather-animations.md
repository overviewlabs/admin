# Dynamic Weather Card in chat

WeatherCard uses the authentic MIT-licensed `teuchezh/dynamic-weather-card` custom element, pinned to the unmodified official v2026.10.1 release. The asset is `/vendor/dynamic-weather-card-2026.10.1.js`; its license is `/licenses/dynamic-weather-card.txt`. Upstream layout, styles, icons and animations are preserved within its shadow DOM. It replaces the previous g3sthousen renderer and dependency entirely.

The snapshot adapter supplies a local Home Assistant-compatible weather entity and forecast subscriptions. These are in-memory callbacks, not network connections or background weather workers. Open-Meteo remains the source; validity/retrieval timestamps and attribution remain outside the upstream card. Default modern styling, high animation quality, glass raindrops and wind effects are used. Clock/aurora are left at upstream defaults. Provider day/night and moon phase override the viewer's location so saved foreign-city snapshots display correctly. Sunrise/sunset scenes require matching provider timestamps.

WMO codes map to upstream sunny/clear-night, partlycloudy/cloudy, rainy/pouring, snowy/snowy-rainy, lightning-rainy, hail and fog. Explicit wind uses windy. Upstream does not offer distinct drizzle, freezing rain, blizzard, smoke or dust graphics: liquid drizzle/freezing rain use rainy, snow variants use snowy; unsupported conditions show an unavailable message rather than inventing sunny weather. Unknown codes remain unknown. Forecast entries must have real ISO dates; descriptive dates are not guessed.

The upstream animation manager caps frames by quality, suspends offscreen/hidden, and honors reduced motion. React retains the web component when snapshots update and removes it on unmount so upstream cleanup runs. No play/pause control or separate temperature/metrics overlay is added. The card keeps its native content-driven height and responsive layout, rather than the previous forced 16:9 canvas frame.

To update, verify an upstream release, replace the versioned asset and license, update the loader URL, run UI typecheck, provider/adapter/component tests and token gates, and verify all native scenes, responsive forecasts, hidden/offscreen suspension and cleanup in Chromium and mobile WebKit before publishing.

## Request-specific cards and depth effects

The original pinned upstream asset remains unchanged. `overview-weather-card` is a thin subclass integrating the user's supplied Snap SVG/TweenMax effect geometry into the existing Canvas frame loop: the 20-segment white lightning path fades over one second, and foreground leaves, snow and curved rim splashes create depth without fixed page-wide SVGs or card shaking. The extension depends explicitly on the pinned v2026.10.1 manager names; browser checks must verify these hooks on upgrades. Foreground particles are capped at 24 and stop with the upstream manager. Medium/30 fps is the efficient default. No additional scheduler, jQuery, Snap SVG or TweenMax dependency is added.

WeatherCard now accepts a validated `weather.card` object: current/forecast/detailed/compact variants; compact/wide/full size; custom title; forecastDays (1–16) and forecastHours (1–24); daily/hourly visibility; grid/strip forecasts; temperature bars, forecast wind, hourly chart; metric, date/clock and effect controls. These are predefined trusted options rather than arbitrary agent CSS/code. Default wide is 56rem with responsive sizing. The scoped foreground gutter prevents effects from overlapping adjacent messages or creating page overflow.

Daily and hourly arrays can be displayed together. Open-Meteo's city tool returns the optional hourly snapshots directly when includeHourly is requested. Requested forecast counts trim provided snapshots; missing dates are never invented. Weekly/N-day answers must pass the actual real forecast entries into the card with forecastDays=N, not merely put a range in the title and a separate table. Missing readings are hidden.
